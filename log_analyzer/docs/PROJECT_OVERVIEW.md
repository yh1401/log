## 1. 项目概述

### 1.1 项目定位

**Log Analyzer** 是一个面向运维工程师、SRE团队和后端开发人员的**智能日志分析平台**。系统通过调用大语言模型（LLM）或规则引擎，对大规模应用日志和网络抓包文件进行结构化分析、错误聚合、根因推断和整改建议生成。

### 1.2 核心能力

- **大规模日志处理**：支持100MB+日志文件，流式分块处理，内存占用稳定在200MB以内
- **智能错误识别**：8类错误模式识别，语义相似度合并，动态内容标准化
- **自动报告生成**：支持PDF、Word、Markdown多种格式
- **网络抓包分析**：PCAP/PCAPNG格式自动解析，协议统计，LLM诊断
- **多用户数据隔离**：基于X-User-Id的用户数据隔离
- **双模式分析**：支持LLM深度分析和规则快速分析两种模式

### 1.3 版本信息

| 版本 | 日期 | 主要更新 |

| v2.5.0 | 2026-06-04 | 操作日志埋点、多用户权限优化 |

## 2. 核心功能模块

### 2.1 日志分析模块

#### 2.1.1 LLM模式
- **语义理解**：支持复杂问题诊断和深度分析
- **根因推断**：提供多层次根因分析
- **智能建议**：基于分析结果生成整改建议
- **响应时间**：5-30秒/1000条日志

#### 2.1.2 规则模式
- **零成本**：不调用外部API，无费用产生
- **极速响应**：<1秒/1000条日志
- **多层次分类**：Critical、High、Medium、Low四个级别
- **8种根因类型**：空引用、资源泄漏、超时、认证、数据库、网络、配置、内存

### 2.2 文件管理模块

#### 2.2.1 文件上传
- **支持格式**：.log、.txt、.zip（自动解压）
- **上传接口**：`POST /api/upload`
- **路径验证**：支持路径输入和文件浏览两种方式

#### 2.2.2 服务器路径读取
- **单一接口**：`POST /api/list-dir`
- **功能模式**：
  - 浏览模式：列出目录内容
  - 验证模式：验证路径有效性
  - 递归模式：扫描子目录
- **权限控制**：白名单机制，支持配置允许访问的目录

### 2.3 任务管理模块

#### 2.3.1 任务创建
- **接口**：`POST /api/process` 或 `POST /api/process-from-path`
- **参数**：
  - `file_path`：文件路径
  - `chunk_size`：分块大小（默认5000）
  - `use_llm`：是否使用LLM（默认True）
  - `force_restart`：是否强制重启（默认False）

#### 2.3.2 任务状态查询
- **接口**：`GET /api/task/{task_id}`
- **状态**：pending、running、completed、failed
- **实时进度**：返回处理进度百分比

### 2.4 报告生成模块

#### 2.4.1 支持格式
| 格式 | 说明 | 文件前缀 |
|------|------|---------|
| PDF | 格式化排版，支持中文 | `report_` |
| Word | 可编辑文档 | `report_` |
| Markdown | 纯文本格式 | `report_` |
| HTML | 网页格式 | `report_` |

#### 2.4.2 报告前缀规则
- **普通任务**：`report_【文件名】_时间戳.html`
- **路径任务**：`report_path_【文件名】_时间戳.html`

### 2.5 操作日志模块

#### 2.5.1 埋点记录
系统自动记录以下操作：
| 操作类型 | 说明 |
|---------|------|
| file_upload | 文件上传 |
| task_start | 任务开始 |
| task_complete | 任务完成 |
| task_failed | 任务失败 |
| page_view | 页面访问 |
| button_click | 按钮点击 |

#### 2.5.2 日志存储
- **存储路径**：`data/action_logs/{user_id}/{date}.json`
- **索引文件**：`data/action_logs/{user_id}/_index.json`

### 2.6 历史报告管理模块

#### 2.6.1 CRUD接口
| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/history/reports` | POST | 创建历史报告记录 |
| `/api/history/reports` | GET | 获取历史报告列表 |
| `/api/history/reports/{report_id}` | GET | 获取报告详情 |
| `/api/history/reports/{report_id}` | PUT | 更新报告 |
| `/api/history/reports/{report_id}` | DELETE | 删除报告 |

## 6. 数据存储方案

### 6.1 目录结构

| 目录 | 路径 | 说明 |
|------|------|------|
| 上传文件 | `data/uploads/{user_id}/` | 用户上传的原始文件 |
| 报告文件 | `data/reports/{user_id}/` | 生成的报告文件 |
| 任务信息 | `data/tasks/` | 任务状态JSON文件 |
| 操作日志 | `data/action_logs/{user_id}/` | 用户操作日志 |

### 6.2 文件命名规则

#### 6.2.1 日志文件
- **普通任务**：`web_process_YYYYMMDD_HHMMSS_文件名.log`
- **路径任务**：`web_path_YYYYMMDD_HHMMSS_文件名.log`

#### 6.2.2 报告文件
- **普通任务**：`report_【文件名】_YYYYMMDD_HHMMSS.html`
- **路径任务**：`report_path_【文件名】_YYYYMMDD_HHMMSS.html`

### 6.3 数据隔离

- **用户隔离**：每个用户的数据存储在独立目录下
- **报告隔离**：报告按用户ID分区存储
- **任务隔离**：任务ID包含用户标识

## 7. 权限与用户管理

### 7.1 用户识别机制

系统采用简化的用户识别机制：
1. 通过HTTP请求头 `X-User-Id` 识别用户
2. 未携带头时使用默认值 `hanmeimei`
3. 支持用户切换和管理员模式

### 7.2 权限级别

| 级别 | 说明 | 适用接口 |
|------|------|---------|
| 公开 | 无需认证 | `/api/health` |
| 用户级 | 需要X-User-Id | 大部分业务接口 |
| 管理员级 | 需要管理员权限 | 无（已移除限制） |

### 7.3 功能访问权限

| 功能 | 权限规则 |

| 操作统计 | 可以查看所有用户的统计数据 |
| 操作类型列表 | 所有用户可访问 |

## 9. 已知问题与解决方案

### 9.1 已解决的问题

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 服务器读取无响应 | 事件监听器绑定问题 | 移除冲突的onclick属性 |
| 模态框关闭失效 | 模态框ID不唯一 | 添加唯一ID并创建专门关闭函数 |
| 任务ID未注册 | 任务创建时未添加到字典 | 在创建任务时同时注册到字典 |
| 日志文件路径错误 | PROJECT_ROOT指向错误 | 使用SCRIPT_DIR.parent定位正确路径 |
| 报告下载失败 | 路径标准化问题 | 正确解析URL编码的路径 |

### 9.2 常见问题排查

#### 问题1：操作日志查询为空
**原因**：埋点函数未被调用

**解决方案**：
- 确保后端导入了操作日志函数
- 检查 `record_file_upload`、`record_task_start` 等函数是否正确调用

#### 问题2：历史报告列表为空
**原因**：接口权限限制或数据隔离

**解决方案**：
- 确认使用正确的用户ID
- 检查 `/api/reports` 接口返回的数据
- 验证报告文件是否存在于正确目录

#### 问题3：管理员功能不可见
**原因**：管理员用户配置不匹配

**解决方案**：
- 检查前端 `ADMIN_USERNAME` 与后端一致
- 确认 `isAdminMode()` 返回正确值
- 验证 `canAccessAdminEntry()` 权限判断

## 10. 快速入门指南

### 10.1 环境要求

- Python 3.10+
- tshark (Wireshark命令行工具)
- 网络连接（使用LLM模式时）

### 10.2 安装步骤

1. **克隆项目**
```bash

3. **启动服务**

```

1. 打开 http://localhost:8000
2. 拖拽或选择日志文件
3. 点击"开始分析"

5. 查看和下载报告

1. 点击"服务器读取"按钮
2. 输入或浏览服务器路径
3. 配置扫描选项
4. 点击确认开始分析
5. 等待处理完成
6. 查看和下载报告

编辑 `config/config.json` 中的 `llm` 部分：
